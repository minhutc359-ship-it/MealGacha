# AW2-019E — Make Pixi maps compatible with strict CSP

VERIFIED REPOSITORY / REMOTE DEPLOYMENT PENDING · 2026-11-02 · base `9338f56b2d4fbd606da2ff7f8d74dc040322f5f3` · branch `master`. Final task SHA is returned in the publication handoff to avoid a self-reference inside the commit.

Owner report: the deployed map shows `Current environment does not allow unsafe-eval, please use pixi.js/unsafe-eval module to enable support.` after the AW2 integration. This explicitly authorizes the minimum production hotfix and its push to `master`; it does not authorize weakening CSP, release promotion, save resets or gameplay/canon changes.

## Root cause

Pixi 8 performs renderer feature checks through generated functions unless its strict-CSP compatibility module is installed. Production correctly serves `script-src 'self'` without `'unsafe-eval'`, while every runtime Pixi entry currently imports `pixi.js` directly. The renderer therefore fails before the first map frame.

## Scope and acceptance criteria

1. Keep the production CSP strict; do not add `'unsafe-eval'`.
2. Add one cached lazy loader that finishes `pixi.js/unsafe-eval` setup before exposing `pixi.js`.
3. Route every runtime Pixi entry used by AW2 maps, destination preloading, the retained original chest and the retained legacy arena source through that loader.
4. Preserve type-only Pixi imports and scene lazy-loading boundaries.
5. Add a focused source contract covering loader order, all runtime call sites and unchanged CSP.
6. Run focused tests, both typechecks and the complete guarded production build; inspect the emitted artifact for the compatibility module and absence of a CSP regression.
7. Update status/evidence; commit and push the verified hotfix to `master`, then compare remote and local SHAs.

## Out of scope

- Gameplay, save schema/data, balance, canon, art/media, dependencies and renderer preference.
- Vercel project settings, domain promotion and external human/device/legal acceptance.
- Rewriting or force-updating any branch.

## Completion

One cached lazy loader now completes `pixi.js/unsafe-eval` before returning `pixi.js`; all seven runtime consumers use it and no production consumer still awaits a direct Pixi import. The deployed policy remains `script-src 'self'` without `'unsafe-eval'`.
