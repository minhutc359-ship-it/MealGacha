## Acceptance criteria

1. Presentation state is derived only from ordered `CombatEvent` values newer than its last serial. Replaying the same batch is idempotent; gaps/out-of-order events are rejected. It contains no HP mutation, damage calculation, reward, quest or save write.
2. Cast/move/projectile/hit/heal/shield/status/interrupt/defeat/terminal events map deterministically to actor animation, projectile, floating text and battle-result presentation. Projectile launch carries an expected impact tick for visual interpolation but hit/miss events remain authoritative.
3. The standalone canvas loads the five approved starter manifests, renders both teams, HP/shield/energy from `CombatBattle`, and uses presentation output for motion/FX/projectiles. It never calls damage/heal/reward logic. Missing assets report a visible error.
4. Auto combat advances only while unpaused. The player can step one tick, reset with level selection, and trigger a valid full-energy ultimate; invalid ultimate attempts stay explicit and do not partially update state. Reduced motion disables interpolation while retaining readable outcome cues.
5. Leveling accepts finite non-negative integer XP, caps at development level 20, has monotonic XP thresholds/stats, and creates immutable starter seeds. Curve/stat numbers are tagged `aw2-leveling-development-v1`, not persisted and not described as approved balance.
6. Tests cover presentation ordering/idempotency/projectile settlement/terminal mapping/no outcome fields; leveling boundaries/monotonic stats/immutability; and unchanged AW2 combat/save/world/assets cases. Browser checks cover load, real atlas pixels, auto tick/pause/step/reset, ultimate event, projectile lifecycle, reduced motion, mobile overflow, error handling and unchanged save bytes.
7. Before VERIFIED run affected AW2 tests, root/dev typechecks, formatter, full unit regression, production build/guard/isolation and headless Chromium. Record exact source/environment/results and all NOT_RUN obligations.

Enemy visuals temporarily reuse starter reference manifests with an explicit treatment and are not authored enemy completion. Browser viewport tests are not physical-device QA. Persisted leveling/save migration and once-only boss reward need a separate task.
