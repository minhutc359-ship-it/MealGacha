2. Interact only within range; four quest states use approved IDs and ordering, accept/close/choice/hand-in are explicit. Three memories count once in any order. Puzzle wrong order retries safely; solved state persists.
3. The five approved N/R starters unlock exactly once on intro quest completion, in the same single-key commit as quest progress. No random draw or duplicate receipt/reward; no reward quantities invented.
4. Boss/combat, chest reward and TCG/Chess entry disclose their pending state and cannot fabricate wins, rewards or mode transitions. Final quest cannot complete without implemented battle verification.
5. AW2 schema v1 loads into a v2 in-memory envelope without writing; explicit subsequent save stores v2. Unknown future schemas/malformed data remain blocked. UUID/createdAt/legacy keys preserved; failures/stale tabs cannot commit local progress or grant duplicate starters.
6. Debug world renders canonical zone/NPC labels with no authored art/model claim. Game rules contain no Pixi/React imports. Production entry excludes the preview and AW2 data.
7. Meaningful rule tests cover boundaries, collision/transfer, range, quest ordering/replay, puzzle retry, migration and atomic starter persistence; browser checks cover movement/dialog/quest/reload/legacy preservation. Run affected checks, root/dev typechecks, full suite after shared save changes and production build. Device/art/battle checks stay NOT_RUN.
