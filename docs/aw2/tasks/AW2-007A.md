Date 2026-10-20. Status: VERIFIED pure rules scope. Roles: BA / mechanic / character / tester / scretary.
Branch `feat/aw2-007a-combat-core`; base `179cc214e4fc8cee37fba34fbfe4416a26742bfb` from `game/adventure-world-2`. PR #79 remains a separate `master` model change and is not a dependency.

## Reason, dependencies and scope

Create the pure rules boundary required before the world boss, renderer, leveling and reward persistence can be connected. The engine must own combat truth; animation consumes immutable events and cannot decide damage, healing, interruption, victory or rewards. D03, D10, D13 and D15 fix the five-unit/manual-ultimate direction and starter identities. Numerical values introduced here are a development tuning baseline, not approved balance or gacha economy.

In scope: serializable battle state; exactly one to five units per side; deterministic target fallback; automatic movement/basic/auto skill decisions; explicit melee contact versus ranged projectile impact; manual ultimate validation; queued casts/impacts; interruption; shields, healing, debuffs and bounded starter passives; battle result; five approved starter kits; pure unit tests and documentation/evidence updates.

Out of scope: React/Pixi renderer, animation playback, world/boss/save adapter, rewards/loot/XP/leveling, enemy content balance, gacha/rates/pity, authored art changes, production route, mobile/device/performance/legal approval. No stable save or AW2 development save schema change.

## Acceptance criteria

1. `src/aw2/combat` exposes immutable/pure commands. Identical initial state + command sequence produces byte-identical state and ordered events; no wall clock, randomness, DOM, React or Pixi dependency.
2. Battle accepts one to five unique living units per side. Canonical five starters use immutable spirit and four skill IDs. Dead/invalid targets fall back deterministically; invalid teams, duplicate IDs and commands are rejected without partial mutation.
3. Basics and auto skills occur only when cooldown, range and target rules allow. Melee damage resolves at contact; ranged damage resolves from a queued projectile impact. Renderer events never confirm or apply gameplay outcomes.
4. Manual ultimate requires a living player unit, full energy, active battle and a valid target when required. Energy is charged once. A pending cast can be interrupted before commit; an already launched projectile is not retroactively cancelled.
5. Than shield/next-basic weaken, Lửa Nhỏ focus chain, Lam Lam bounded overheal shield, Mộc Non distinct-ally support cadence and Sương Lành per-target slow are finite/capped and cannot self-loop. Starter direction follows approved AW2-003 identities without claiming final numerical balance.
6. Battle ends exactly once when one side has no living actors. No loot, quest completion, world flag or save write occurs in the combat core.
7. Tests cover deterministic replay/serialization, five-unit limit, target fallback, melee/ranged timing, auto skill behavior, ultimate validation/spend, interrupt boundaries, passive caps, simultaneous terminal handling and unchanged caller input. Run affected AW2 tests, both typechecks, full unit suite and production build before VERIFIED; record failures honestly.
