## Reason and scope

Establish the first AW2 runtime boundary before world, roster or rewards are implemented. Persist only a versioned, empty progression envelope under an AW2 development key. Provide a standalone development screen to create, reload, inspect and explicitly reset that envelope. Avoid mounting the legacy app or its save/bootstrap services on this screen.

In scope: strict save validation; read-only load; blocked writes for malformed/future saves; storage failure handling; stale-write/reset protection; per-reset typed confirmation and cancel; independent development HTML entry; focused automated save tests and browser UX checks; required status/handoff records.

Out of scope: authored map/characters, gacha and economy, reward grants, gameplay, legacy migrations/import, production AW2 launch, native persistence, reset of Soul of Meal data, deployment or merge. AW2-002/003 remain subsequent work; their draft canon is not approved through this task.

## Acceptance criteria

1. AW2 saves use only `aw2.development.save`; no legacy key is read, changed or removed. Reading an absent save never creates one.
2. The schema identifies AW2, development channel and version 1; validates save identity, timestamps and revision; rejects unknown or invalid progression fields. No proposed roster or gacha values enter the save.
3. Create/save/reload preserve envelope identity and creation time; successful writes advance revision. Malformed, foreign or unsupported saves are preserved byte for byte and cannot be overwritten by normal save.
4. Reset requires a newly opened confirmation dialog, exact `RESET AW2` input and final explicit action. Cancel, Escape, stale data, missing confirmation and failed writes preserve existing data. Reset writes a fresh AW2 envelope atomically to its one key; it never calls storage clear/remove.
5. Cross-tab stale writes/resets are rejected. Serialize cooperating browser writers with the Web Locks API; if unavailable, block mutations and explain why. Compare the exact stored bytes again inside the lock. No claim of reward atomicity is made.
6. The development screen reports unavailable storage, write failures and invalid/future saves without falsely reporting success. It is reachable independently at `/dev/aw2/index.html` through `pnpm dev` and excluded from the production entry graph.
7. Focused tests cover SAVE-01, plus schema/load/reset/conflict/failure cases. Run root/dev typechecks, production build and relevant existing save regressions. Browser coverage must state actual engine and viewport; physical-device QA remains NOT_RUN.

## Risks and sign-offs

Storage can be denied, full or modified by another tab. Save version 1 has no gameplay yet; extend it deliberately when the next feature owns its schema. Browser Web Locks support is required for writes in this foundation; native/offline guarantees are deferred. Existing stable services are intentionally outside this entry's dependency graph.

Required role reviews: BA scope/AC, mechanic save/reset design, tester observed results, scretary status and handoff. These are persisted role reviews performed in-session, not background agents or owner approval of proposed canon. Owner review remains required before merge/release and any future production migration policy change.
