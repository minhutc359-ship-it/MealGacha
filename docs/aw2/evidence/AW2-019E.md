# AW2-019E — strict-CSP Pixi map hotfix evidence

2026-11-02 · `master` · base `9338f56b2d4fbd606da2ff7f8d74dc040322f5f3` · Linux x64 · Node24.22.1 · pnpm10.34.3 · TypeScript5.9.3 · Vite8.0.5 · Vitest5.0.1. [Task](../tasks/AW2-019E.md).

## Defect and repair

The deployed renderer reported `Current environment does not allow unsafe-eval, please use pixi.js/unsafe-eval module to enable support.` Pixi8.20.1 checks generated renderer functions when an `Application` is constructed. The production CSP correctly allows only same-origin scripts and does not allow `unsafe-eval`, but the runtime had imported `pixi.js` directly without first installing Pixi's strict-CSP static factories.

`loadPixi` now caches one promise and completes `import("pixi.js/unsafe-eval")` before `import("pixi.js")`. All three lazy landscape renderers, the flat/interior renderer, destination preloading, original chest effects and retained arena source use it. Type-only imports and scene lazy boundaries remain unchanged. `vercel.json` remains `script-src 'self'`; no `'unsafe-eval'` permission was added.
