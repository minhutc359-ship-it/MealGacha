# TCG-003 · Chest economy and complete battle loop

Status: COMPLETE — 04/11/2026.

## Reason

The production cutover is stable, but Chest rewards are not yet committed into Tactical progress and battle reactions/boss phases are still presentation placeholders.

## In scope

- Convert every newly revealed Chest reward into a deterministic Tactical receipt: one canonical card plus Tinh Vi for duplicate copies, exactly once.
- Show Tactical reward value and synchronization status in the Chest reveal flow.
- Add authored traps, a reaction window, boss phases and first-battle guidance to the 4x2 engine/UI.
- Preserve campaign/PvP isolation, migration safety and existing Chest collection data.
- Add focused tests, full regression, package verification, documentation, commit and push to `game/tactical-tcg`.

## Out of scope

- Server-ranked PvP, payments, account/cloud save, merge to `master`, Vercel deployment and destructive save resets.

## Acceptance criteria

1. A Chest reward maps to a canonical card and creates a stable receipt derived from the Chest reward id.
2. Replaying, reopening or reloading cannot grant the same Chest reward twice.
3. The first copy grants a card; later copies grant Tinh Vi according to rarity without changing PvP rating/power.
4. Battles expose trap placement/triggering, a deterministic reaction phase and visible two-stage boss behavior.
5. Tutorial, reduced-motion and responsive controls remain usable.
6. Typecheck, focused tests, full test suite, release records and production build pass.

## Risks and test impact

- Cross-storage transaction ordering between the legacy Chest save and Tactical progress: never roll back or delete the legacy reward.
- Browser reload during reveal: the bridge must recover by receipt id on the next mount.
- Engine state/replay compatibility: all new actions remain pure and idempotent.
- Required sign-offs: mechanic, tester and documentation/handoff evidence.

## Completion

- Chest grants use `chest:<reward-id>` receipts; migrated ownership and interrupted reveals are recovered without deleting legacy rewards.
- The battle reducer now owns trap placement/triggering, campaign/PvP merge counts, a usable reaction window and authored boss phases.
- First-battle guidance, responsive trap controls, reduced-motion behavior and a lazy Manga boundary are present in production UI.
- In-session mechanic/tester/documentation review: PASS. Independent desktop/mobile physical-device review: NOT RUN and remains a pre-merge gate.
