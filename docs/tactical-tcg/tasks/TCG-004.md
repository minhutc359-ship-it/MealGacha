# TCG-004 · Tactical UI completion

Status: COMPLETE — 04/11/2026.

## Goal

Bring the shipped Chest/battle mechanics to production-quality presentation without changing deterministic combat or save contracts.

## In scope

- Redesign the 4×2 battle hierarchy, commander health, unit cards, empty cells, trap selection, reaction, boss phases, result and combat log.
- Make selected-unit stats, role/trait information, shield/energy and actionable Ultimate timing readable.
- Polish campaign nodes and Chest Tactical reward presentation to match the same visual language.
- Preserve keyboard focus, touch targets, responsive layout and reduced-motion support.
- Add source-level UI regression coverage, run full tests/build, document and push to `game/tactical-tcg`.

## Out of scope

- New numerical balance, new reward schema, server PvP, deployment, master merge and destructive save changes.

## Acceptance

1. Battle status and both commander HP values are readable without opening the log.
2. Unit HP, energy, shield, role, star and boss phase are visible at desktop and mobile widths.
3. Trap placement clearly identifies selected column/type and current armed trap.
4. Reaction, result and tutorial surfaces have accessible live/status semantics.
5. No nested interactive controls, horizontal page overflow or mandatory animation.
6. Typecheck, focused UI tests, full suite, release verification and production build pass.

## Completion

- Battle, campaign and Chest Tactical reward surfaces now share the jade/gold tactical visual language.
- Real SSR markup verifies sixteen cells, eight campaign nodes, progress semantics and no nested buttons.
- Desktop/tablet/mobile breakpoints and reduced-motion fallbacks are implemented in scoped CSS.
- In-session UI/accessibility/source review: PASS. Independent physical-device visual/touch review: NOT RUN and remains a pre-merge gate.
